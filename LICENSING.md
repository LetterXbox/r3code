# Licensing

R3 Code is licensed **component by component**. Two rules decide which license
applies to a file:

1. **R3-authored material is AGPL-3.0-only.** Anything written for this project
   whose rights are held by Jason Kneen is offered under the GNU Affero General
   Public License, version 3 only. The full text is in `LICENSE`.
2. **Material that is T3 Code-derived *in substance* keeps its T3 Code MIT
   license.** That means content or format taken from the upstream T3 Code
   project — copied copy/labels, generated data extracted from upstream source,
   matching wire contracts, upstream message catalogs, or upstream assets — even
   when the file was produced or rewritten by R3 tooling. Those files are listed
   in `COMPONENT-LICENSES.md` and remain subject to
   `LICENSES/T3-Code-MIT.txt`.

Rule 2 is not optional: R3 does not hold relicensing rights over T3 Code
material, so nothing derived from upstream is relicensed as AGPL. Where a file
mixes both, it is listed as T3-derived.

## What is AGPL-3.0-only

Unless a path appears in `COMPONENT-LICENSES.md` under "T3 Code-derived", the
file is R3-authored and licensed AGPL-3.0-only. This includes the native macOS
client (`t3ui/`), the Rust server implementation (`server-rs/src/`), the build,
packaging, release and runtime-staging tooling (`tools/`), the test suites, and
the project's own documentation.

## What is T3 Code-derived (MIT, retained)

The authoritative list is `COMPONENT-LICENSES.md`. In summary it covers:

- the localisation catalogs (`t3ui/i18n/translations/`) whose keys and ICU
  message formats are upstream T3 Code's;
- data files generated by reading upstream source (settings panels and nav,
  theme palette data and previews, RPC result schemas and concurrency rules,
  sound assets);
- the file-type and document-viewer icon sets, plus the "T3" branded provider
  marks that identify upstream file types;
- the bundled document-viewer pages built from the doc-viewer sources.

## Third-party components

Third-party and vendored components retain their own licenses and notices; this
document does not change them:

| Component | License | Notice |
| --- | --- | --- |
| NSH (native host) | Apache-2.0 | `LICENSES/NSH-APACHE-2.0.txt` |
| GPUI Fast | Apache-2.0 | `LICENSES/GPUI-FAST-APACHE-2.0.txt` |
| CPython 3.11.18 (pinned python-build-standalone build) | PSF | `LICENSES/CPython-3.11.txt` |
| T3 Code | MIT | `LICENSES/T3-Code-MIT.txt` |
| Bricolage Grotesque (UI font) | SIL OFL 1.1 | `LICENSES/Bricolage-OFL-1.1.txt` |

The theme helper bundles Python 3.11.18 from the pinned
python-build-standalone archive (`python-runtime.json`); the runtime keeps its
packaged third-party notices.

The About license viewer includes a generated inventory of 620 native host
dependencies for the Apple silicon build, with their detected license texts.
That inventory was produced with cargo-about 0.8.4 against the locked host
dependency graph. Its diagnostics include two deprecated GPL-2.0 identifier
parsing errors, so those results and any separate NOTICE requirements still
require review. The server-provided third-party notice manifest covers the
upstream server and web dependencies; it is not a complete inventory of every
component in R3.

To regenerate the native inventory, run `cargo about generate --config
/path/to/r3/tools/native-licenses-about.toml --manifest-path
nsh-gpui-host/Cargo.toml --target aarch64-apple-darwin --locked --format json
--fail > /tmp/r3-native-about.json` from
`third_party/nsh-host-combined-src/crates/gpui`, then run `python3
tools/generate_native_licenses.py --input /tmp/r3-native-about.json --output
t3ui/pages/settings/nativeDependencyNotices.ts` from the R3 root. Review the
cargo-about diagnostics and the generated notices before distribution.

## Outstanding review

The repository still carries a pre-existing Apache-2.0 workspace declaration in
the Rust workspace metadata. `server-rs/Cargo.toml` sets `publish = false` and
declares no license field, so the AGPL-3.0-only terms above are the operative
ones, but that stale declaration should be replaced when the workspace metadata
is next touched. A file-level provenance audit of contributions made before this
licensing scheme is also still outstanding.
