# R3 Code release readiness

This is a working release audit, not a release approval. The current bundle is a local development candidate and must not be published as a standalone installer yet.

## Confirmed gaps

- The bundle builder can include the published T3 0.1.9 runtime, a native local-server supervisor and a pinned standalone Python runtime for the theme helper. Isolated supervisor and fake-host launcher tests cover private bootstrap creation, R3 client authentication, project and thread creation, locking and shutdown. The supervisor also accepts an existing owner-controlled, readable T3 directory without changing its permissions, while rejecting directories writable by others. Clean-machine startup, real providers, and runtime operation on migrated production-data copies have not been verified.
- The bundle builder now uses `com.jasonkneen.r3code` as its macOS identifier. The existing NSH internal app id remains `com.example.t3ui` to preserve its storage path. The new bundle identifier can cause macOS to request permissions again; the resulting installed-app behavior has not been verified.
- The current native supervisor defaults to the existing `~/.t3` data directory when no connection settings are present. Starting the app can therefore open or migrate T3's data. Both T3 and R3 databases were backed up before installation, but runtime behavior against those real databases has not been tested.
- The installed local build is ad-hoc signed. A separate candidate and DMG were signed with Developer ID and the hardened runtime. Notarization, stapling and a clean-machine Gatekeeper check remain outstanding: the existing `infinitty` notarytool profile reached Apple, but Apple returned HTTP 403 because a developer agreement is missing or expired. The account holder must resolve it.
- The privacy policy is a draft. The source and dependency license provenance audit and complete third-party notices remain unfinished; the repository still declares Apache-2.0 for the original Rust workspace while R3's stated license is AGPL-3.0-only. A generated Apple silicon native dependency inventory now contains 620 crates and their detected license texts. Cargo-about logged two deprecated GPL-2.0 identifier parsing errors that need review, and separate NOTICE requirements have not been fully checked.
- A source-review archive was staged against a candidate whose non-ignored input fingerprints match the recorded build inputs. A redacted gitleaks scan of the R3 and native-host portions returned 29 possible matches, including test webhook tokens and public configuration; review them before sharing. The upstream source archives inside it were not scanned in that pass. Later source changes require a fresh candidate and archive.
- The worktree contains substantial uncommitted changes. Build identity marks this as dirty; a release must identify and review the exact source and upstream server inputs.
- This repository currently has no configured Git remote. The NSH host is a separate, locally modified checkout (`277cb9e8c23d6692755152b503099b9770693ba8` at this audit), including an untracked native vendor directory. Its source and notices must be captured alongside R3's exact release source before distribution. No repository has been pushed.
- User-reported interaction and visual parity items remain open in `R3_PARITY_CHECKLIST.md`. The user has requested that R3 not be launched, so live startup and side-by-side acceptance have not been run.

## Candidate source and theme controls

- Use `tools/rebuild_r3_app.py --default-theme --capture-source --server-archive <verified-t3-archive> --python-archive <pinned-python-archive> --output <candidate.app>` for a candidate. The default-theme option avoids packaging the builder's saved theme and custom themes. The source option fingerprints the non-ignored R3 and native-host inputs before and after building. Do not use `--skip-host-build` to claim that the packaged native host was compiled from the recorded host checkout.
- `tools/stage_r3_source.py` checks recorded input fingerprints again before and after staging. These fingerprints detect changes to the enumerated checkout inputs; they do not capture ignored build dependencies, prove bit-for-bit reproducibility, settle licensing, or replace a sensitive-content review. Inspect the archive before sharing.

Its app signature was verified, the saved local theme was retained, and the supervisor, fake-host launcher and theme helper passed isolated tests. `/Applications/.R3 Code-previous-20261115T010224512232Z.app` retains the prior app, and a private backup of the R3 and T3 databases is in `~/.t3codegpui/release-backups/20261115T010020004656Z`. The mounted DMG signature, Applications shortcut, server hash, Python runtime and notices were verified. The signed Python helper answered an isolated theme request. The DMG is not notarized or stapled, and the source snapshot still needs sensitive-content and license review.
